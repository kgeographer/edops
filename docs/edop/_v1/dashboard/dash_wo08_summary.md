# dash WO-08 summary: HYDE as line graphs, a server time limit, lighter slice steps

2026-11-18. Spec `dash_wo08_HYDE-line-graphs.md`; record `dash_wo08_results.md`. Branch `dashboard`. Commits `b159515`, `a15f770`, `d28dacb`, `cf36043`. Nothing deployed; the Sandbox page is unchanged. Gate (Karl, in a browser): Lviv 1900-2000 HYDE as lines, passed; the time-limit message, passed (forced with a 1 ms limit); stepping through Northern Song slices is quick (built; the 33 ms request is measured).

- **Item 1, HYDE as lines.** One line chart (about 340 x 118 px, the size of two LMR charts) with a dot at each HYDE step, km² on one axis: cropland green, pasture purple, rangeland orange. Karl chose it over four small charts and over three stacked full-width charts (screenshots in the results note). **Grazing is not drawn**: conceptually it is pasture plus rangeland, so the display shows those two; the payload and API are unchanged (the source has grazing above the sum in some cells, WO-02 issue 8). A span with no step keeps its text (the nearest step, with the "~" note). The 12-step limit for a single basin and a ring is removed; the buffer limit (9) stays.
- **Item 2, server time limit.** 20 s on the HYDE part of Band T (the query and the reduction), set by `EDOPS_BAND_T_TIME_LIMIT_S`. When it is hit the engine raises one error; `/api/areas` and the public `scope=buffer` and `scope=area` answer 504 with a plain message; the Dashboard shows it in yellow (placeholder wording). The page's 5 s estimate stays as its own gate; this is the guarantee behind it. A limit of 0.05 s does not trip a single basin (HYDE for one basin is quicker than that); 0.001 s does.
- **Item 3, lighter slice steps.** A slice step (Next, Prev, First, the slider, choosing a polity) asks `/api/areas` with `members_only=true` and gets the member ids and the resolver from the crosswalk table: about 33 ms, against 1.9 to 3.3 s for the leanest signature request and up to 15 s for the full one (China 2000-2023). The ids are identical. The option is off by default; no other caller is affected.
- **Item 4, HYDE histograms.** Nothing on the page, in the API guide or in the baseline tests reads HYDE's histograms. They are 23 to 34% of HYDE's time (China 2000-2023 10.1 s to 7.8 s; Northern Song 1000-1999 7.0 s to 4.6 s), less than expected. Karl's rule: the Dashboard never draws them, the public `detail` payload stays as it is. So `skip_hyde_distribution` is an off-by-default option on `/api/areas` that the Dashboard sends; p10, p90, sd and the totals stay. Dropping HYDE's histograms altogether is not proposed.

Tests: dashboard folder, engine and regionality (16 baseline payloads, unchanged) and the areas tests, 516 passed (7 min 32 s), run before the item 4 commit.

Needs attention: the biggest slices (Canada-sized, about 19 s estimated after item 4) are still over 5 s, and only the 20 s limit stops them; see the results note.
